## Security and access

| Finding | Change | Source |
| --- | --- | --- |
| Any signed-in user (clients included) could register a webhook for every event of every client. | `/api/mcp/subscriptions` is staff-only (`clients.view`); events are validated against `WEBHOOK_EVENTS`; the destination is validated on creation; hooks record `ownerId`, and owned hooks receive only events whose `clientId` the owner can still access, checked at dispatch and again at drain. Hooks without a name no longer break listing. | `app/api/mcp/subscriptions/route.ts`, `lib/webhooks.ts`, `lib/webhook-security.ts` |
| Reset and invitation links took their host from `X-Forwarded-Host` when `APP_URL` was unset (unset in production). | In production `appBaseUrl` uses only `APP_URL`/`NEXT_PUBLIC_APP_URL` and throws if neither is set; request headers are never used. `APP_URL` is a `[vars]` entry in `wrangler.production.toml`. | `lib/client-status.ts` |
| No security headers. | CSP, `frame-ancestors 'none'`/`X-Frame-Options: DENY`, HSTS (not in dev), `Referrer-Policy: no-referrer`, `nosniff` and Permissions-Policy on every path via `next.config.ts` `headers()`. `script-src` keeps `'unsafe-inline'` because Next streams inline data scripts; `img-src` is `'self' data: blob:` so rendered markdown cannot load remote images. | `lib/security-headers.ts`, `next.config.ts` |
| Clients received staff-only task fields, internal-task evidence, staff activity and documents of internal tasks. | One client projection (`clientSafeTask`, `clientCanSeeDocument`, `clientSafeActivity` with the `CLIENT_VISIBLE_ACTIVITY` allowlist) is applied to tasks, task PATCH responses, evidence, activity, documents, content, search and MCP (including context packs). MCP never returns `internalNotes`. | `lib/client-projection.ts`, routes listed in the file header |
| Clients could approve their own approval requests. | Reviewers cannot be the requester; clients review only staff-requested approvals (`requestedByRole`, with a user lookup for older records). Hodi-created approvals record the role. | `lib/project-operations.ts` |
| Client records accepted any status and unbounded fields. | Zod schemas for create, PATCH and bulk: enum status and stage, active staff assignee, length and count limits, email format. | `lib/client-validation.ts` |
| Clients could read and refresh the Hodi queue; a GET wrote data. | Queue routes and functions are staff-only; refresh is POST only; `filterAssignedClients` returns only the client's own record for a client session. Hodi proposals are listed to staff only and include `failed`. | `app/api/hodi/**`, `lib/hodi-queue.ts`, `lib/client-access.ts` |
| Login and forgot-password revealed which accounts exist. | Login always runs scrypt (dummy hash for unknown users) and returns the generic 401 unless the password is correct; forgot-password does its lookup, credential issue and mail after the response. | `app/api/auth/**`, `lib/after-response.ts` |
| MCP tokens survived password change, reset and sign-out-everywhere; legacy sessions skipped the version check. | Identities store `authzVersion` (missing counts as 0) and session revocation also revokes the user's MCP identities. Missing session versions count as 0. | `lib/mcp-auth.ts`, `lib/auth.ts` |
| MCP approvals did not bind the payload; reviewers could approve their own requests. | Requests store a `payloadHash`; apply writes the approved payload, only the requester may apply, and a `McpApprovalApplication` document created with an `exists: false` precondition makes apply single-use. | `lib/mcp-controls.ts` |
| Git validation ran commands in any caller-supplied directory. | Checkouts resolve inside `BOATSHIP_GIT_CHECKOUT_ROOT` (realpath containment); only known checks and plain revisions are accepted; validation is disabled (501) when the root is unset and always on Workers. | `lib/git-validation.ts`, `app/api/tasks/[id]/validate-progress/route.ts` |
| Admin-issued MCP tokens did not record the issuer; project ids were unchecked. | `issuedBy` is stored and audited (`mcp.identity.issued` / `regenerated`); project ids must be accessible to the token owner. | `app/api/mcp/identities/route.ts` |
| Outbound webhooks signed `sha256(secret.body)` without a timestamp. | `X-Boatship-Signature` is hex HMAC-SHA256 of `${X-Boatship-Timestamp}.${body}`. **Receivers must update their verification.** | `lib/webhook-security.ts` |
| Git webhooks could be replayed with a new delivery id; repository existence leaked before the signature check. | The signature is verified first; dedupe keys on the body hash; stale heads are stored as evidence flagged `stale` without moving the task link (a legitimate force-push back to an earlier SHA is also treated as stale). | `app/api/git/webhooks/[provider]/route.ts`, `lib/git-webhook-guard.ts` |

## Hodi and integrations

- Connected-app (Composio) tools are classified by name (`lib/composio-policy.ts`): read-only tools run; write or unknown tools become a `run_connected_app_tools` proposal shown on the existing approval card and executed through `/api/agent/actions/execute` after approval. The Composio session runs without its sandbox.
- Chat history is rebuilt from server-stored turns; only the latest user text is taken from the request. Output is capped at 4,096 tokens per step and history at 48k characters (`lib/agent-chat-policy.ts`).
- Hodi action payloads are key-whitelisted with validated enums (`lib/hodi-action-policy.ts`); previews show every written field, including whether a task is client-visible. A failure after validation marks the proposal `failed` instead of returning it to `pending`.
- Integration and secrets routes require `integrations.manage`; the test endpoint builds fixed arguments; disconnect checks that the account belongs to the caller. The workspace credentials panel is admin-only. New user secrets bind ciphertext to user and provider (`keyVersion` 2); version 1 rows still decrypt.
- Markdown images in chat render as links.

## Storage, files and operations

- Only changed snapshot slices are size-checked; the cap is 900 KB on Firestore and 64 MiB on PostgreSQL (`sliceByteLimit`).
- Retention (`lib/store-retention.ts`): finished webhook deliveries older than 30 days (cap 2,000), the last 500 integration runs, read notifications for 30 days, activity capped at 3,000 with overflow moved to `ActivityArchive` in the same transaction. Audit and GDPR exports include archived activity. Messages are not pruned.
- Uploads decode once without extra copies; downloads with a Range header read only the requested bytes from the blob table (`readDocumentContentRange`).
- PostgreSQL gains expression indexes on `createdAt`, `status` and `expiresAt` used by string equality, `in` and range filters; integration-job listing sorts and limits in SQL; the per-miss profile count is gone.
- Writes to user profiles, engagements, contacts and notifications now advance the Redis cache version.
- Optional `DATABASE_CA_CERT` verifies direct connections; `sslmode=disable` is honoured only for loopback hosts.
- Test suites that create and drop tables read `TEST_DATABASE_URL`, refuse non-local hosts unless `QA_ALLOW_REMOTE_DATABASE=1`, and no longer load `.env.local`; the QA fixture applies the same guard. CI adds a `postgres:16` job and a Cloudflare dry run (neither has run yet).
- ZeptoMail requests time out after 10 s. The slice cache is dropped when the snapshot version goes backwards (after a restore).
- `docs/operations/backup-restore.md` is rewritten for the PostgreSQL service; its backup properties are unverified.
- The cron uses `APP_URL` instead of the old custom domain. `wrangler.toml` is a preview-only config (`boatship-onboarding-preview`, no route) and must not be deployed. `[observability.issues]` is enabled; whether errors bypass the 10% head sampling is unverified.

## Interface

- Average onboarding days divided by the wrong constant (10× too high); fixed with one helper. Overdue analytics compare calendar days.
- Navigation, Settings and the command palette share one visibility predicate that follows the API capability rules; calendar and compliance controls are hidden without their capabilities.
- GDPR delete no longer auto-selects a client and requires typing the company name; confirmations (with counts and names) guard bulk client and document changes, MCP revoke/regenerate, integration disconnect and portal approval. MCP revoke was previously broken (missing id) and now works.
- Sign-in honours a safe, role-appropriate `?next=`; logout always clears local state; a failed first session check shows a retry screen; session requests are de-duplicated.
- Route-group `error.tsx`/`loading.tsx` and `global-error.tsx` exist. The portal home loads its sections independently.
- The Hodi drawer is `inert` when closed and a modal dialog on narrow screens; the command palette has a focus trap and combobox semantics.
- Hard-coded light colours are replaced with tokens (the dashboard hover made text invisible in dark mode); `--ink-faint` meets 4.5:1 in both themes.
- Date-only due dates display as calendar days in every timezone; timezone fallbacks are UTC.
- Copy uses "engagement" except for the onboarding-only metric; `metadataBase` follows `APP_URL`.

## Dependencies

`npm audit fix` and wrangler 4.152.0 clear every production advisory. Development-only advisories remain in wrangler/miniflare, OpenNext's dotenvx and firebase-tools (undici 6, uuid, OpenTelemetry) and need upstream releases.

## Release notes

1. Webhook receivers must switch to the HMAC-with-timestamp verification before this is deployed, or every delivery will fail.
2. `APP_URL` is required in production; without it, mail containing links fails with a configuration error.
3. Existing MCP tokens for users whose `authzVersion` is above 0 stop working and must be regenerated.
4. Set `BOATSHIP_GIT_CHECKOUT_ROOT` only on a Node host that should run Git validation; it stays disabled on Workers.
5. Watch the browser console after deploy for anything the new CSP blocks.
