# Interface redesign (Regatta), 2026-10-23

Implemented in the working tree on 2026-10-23 after the user chose the "Regatta" direction from four proposals. This record describes the presentation layer; data model, API routes, roles and flows are unchanged. The full token and component reference is [DESIGN.md](../DESIGN.md).

## What changed

- **Tokens and theme.** `app/globals.css` defines the whole palette on `:root`, with dark values under `[data-theme="dark"]` and under `prefers-color-scheme: dark` when no explicit choice is set. The previous variable names (`--ink`, `--ink-muted`, `--border`, `--brand`, `--surface*`, `--danger`, `--success`, `--warning`) are kept with new values so every page picked up the new palette at once; new names (`--brand-soft`, `--on-brand`, `--accent-*`, `--*-soft` status tints, `--nav-*`, `--radius-*`, shadows) were added for new work. `--accent` now means the orange headline colour; pages that used it as a link colour were moved to `--brand`.
- **Fonts.** `app/layout.tsx` loads Bricolage Grotesque, Figtree and Space Mono through `next/font` and exposes them as `--font-display`, `--font-sans` and `--font-mono`. An inline script applies the stored theme before first paint.
- **Component kit.** `components/shared/ui.tsx` was rewritten against the tokens. Existing exports keep their signatures; `ButtonLink`, `buttonClasses`, `Hint`, `StatTile`, `Kbd`, `SectionHeading` and `Tabs` are new. Button gained an `accent` variant; Badge gained `brand` and `accent` tones; Modal becomes a bottom sheet on phones.
- **Team shell.** `components/admin/AdminShell.tsx` and the new `components/admin/navigation.ts`: a cobalt rail with three groups (Work, Operate, Hodi), a Settings entry, a top strip with a search button that opens the command palette, a theme toggle and notifications. Settings routes (account, workspace policies, service templates, forms, reminders, automations, integrations, webhooks, MCP access, compliance) left the primary rail; inside them the rail shows the settings list, and the new `app/(admin)/settings/page.tsx` hub lists them as cards. `proxy.ts` includes `/settings` in the staff route list. Admin-only and permission-gated items keep the same visibility rules as before.
- **Client shell.** `components/client/ClientShell.tsx`: top bar with Home, Tasks, Documents and Messages, a More menu for Engagements, Forms, Approvals and Account, and a five-slot bottom tab bar on phones. `app/(client)/portal/page.tsx` opens on an orange "Your next step" card; its data loading and derived values are unchanged.
- **Command palette.** `components/shared/CommandPalette.tsx` lists every rail and settings route, exposes `openCommandPalette()` for the search buttons, and uses the new tokens. `components/shared/NotificationBell.tsx` and `components/shared/AccountSettings.tsx` (which gained an Appearance section with `ThemePicker`) were restyled.
- **Public pages.** `app/page.tsx` and `app/page.module.css` were rewritten in the new system and follow the theme; `app/global-not-found.tsx` shares those styles. The unused marketing loader (`components/marketing/*`, `app/home.module.css`) was removed. `app/login/page.tsx` is a split layout with a cobalt side panel.
- **Page migration.** A scripted pass over 40 page and component files replaced Tailwind palette colours (`red-*`, `emerald-*`, `amber-*`, `bg-white`), hex literals and `text-white`-on-brand with tokens, and moved fixed radii to the radius tokens. Pages otherwise keep their structure and still consume the shared kit, so they render in the new look in both themes.

## Structural pass, later on 2026-10-23

The three layout changes the first pass left as proposals were then implemented. Data model, API routes, roles and permission checks are unchanged; every action below calls the same endpoint it did before.

- **Record pages.** `RecordHeader` in `components/shared/ui.tsx` is a sticky header (back link, title, status badges, owner, next milestone, actions) that holds the record's `Tabs`. `app/(admin)/clients/[id]/page.tsx` uses it with eight tabs: Overview, Engagements, Tasks, Forms, Documents, Messages, Billing and Vessels. The open tab is the `?tab=` query parameter (read with `useSearchParams` inside a `Suspense` boundary; `router.replace` without scrolling), so links from the Inbox, notifications and Hodi can open a section directly and the browser back button works. The former People and Timeline tabs are sections at the foot of Overview; `components/clients/ClientWorkspaceNav.tsx` was removed. The Forms and Documents tabs show counts of submissions and files awaiting review. Messages embeds `components/clients/ClientMessagesPanel.tsx`, the client's portal thread with the same `/api/messages` reads, writes, realtime socket and polling fallback as the Messages page, scoped to the client with the same engagement context choice; a link opens the full page. Billing summarises engagements and progress and points administrators at the workspace ledger, because accounting entries carry no client id; it does not invent per-client invoices. `app/(admin)/products/[id]/page.tsx` has the same header-plus-tabs shape with its existing Overview, Roadmap, Work, Releases and Settings tabs, also in `?tab=`.
- **Inbox.** `app/(admin)/tasks/page.tsx` is now one triage list; the rail entry is "Inbox" with the inbox icon, which the command palette picks up from `navigation.ts`. No route was added, so `proxy.ts` is unchanged and the MCP decision notification that links to `/tasks` still lands here. Rows come from the existing endpoints: pending MCP write requests (`/api/mcp/approvals`) and task completions (`/api/tasks/approvals`), form submissions with status `submitted` (the visible clients from `/api/clients`, then `/api/forms?clientId=` per client, as there is no cross-client forms endpoint), and unread `message` notifications from `/api/notifications` grouped by thread link. Filter chips (Everything, Approvals, Form submissions, Messages) carry counts. `j`/`k` or the arrow keys move the highlight, Enter expands an approval's inline review (the same reason field and approve/reject calls as before) or opens any other row, `o` opens the linked place, Escape collapses. Opening a message thread marks its notifications read through the existing `PATCH /api/notifications` before navigating. The Messages page is unchanged.
- **Hodi drawer.** The chat logic moved from `app/(admin)/agent/page.tsx` into `components/hodi/HodiChat.tsx` with a `variant`: `page` is the full workspace with the history rail (the `/agent` page renders it; `/hodi` is untouched), `drawer` keeps the history in a menu. `components/admin/HodiDrawer.tsx` is the right-hand panel: a Hodi button in the top strip opens it (hidden on `/agent`), it is a fixed overlay below `xl` and a 28rem column beside the page from `xl`, Escape closes it, focus returns to the button, and it stays mounted after the first open so a conversation survives closing. On `/clients/[id]`, `/products/[id]` and `/tasks` the drawer passes a context (record name fetched from the record's own endpoint) that the chat shows as a chip, uses for its suggestion prompts and prefixes to the first message of a chat as plain text, so Hodi's retrieval finds the right records without any change to `/api/agent/chat`.

## Not done

- Billing stays a summary until accounting entries can reference a client.
- The Inbox reads forms per client; with many clients that is one request per client on each load.
- The drawer's conversation state is the chat component's own; the page and the drawer do not share an open conversation, only the stored history.
